# 运行时颜色修正管线

## 问题模型

BodyAddon 的最终颜色可能同时受以下来源影响：

- 种族或身体部件的静态 Def；
- 基因提供的颜色语义；
- 上游渲染节点选择的纹理与 Shader；
- Graphic 数据库缓存；
- 其他兼容 Mod 的前置或后置补丁。

若只在较低层修改纹理路径或临时颜色，后续渲染步骤可能重新创建 Graphic 并覆盖修改。架构因此选择在“上游已完成图形选择、即将交付渲染”的边界做最终校验。

## 处理流程

```text
最终 Graphic + Pawn + BodyAddon 节点
                │
                ▼
        是否属于目标种族？ ──否──► 原样返回
                │是
                ▼
        是否为目标耳/尾节点？ ─否─► 原样返回
                │是
                ▼
        兼容基因/扩展是否适用？ ─否► 原样返回
                │是
                ▼
          计算预期颜色对
                │
                ▼
          当前颜色是否一致？ ─是──► 原样返回
                │否
                ▼
      保留纹理与绘制参数，仅重新着色
```

## 关键设计选择

### 保留上游的纹理决策

运行时修正不得自行维护一份完整纹理路径白名单并重新选择纹理。它应接收上游最终结果，保留：

- 主纹理及附加纹理；
- Shader；
- drawSize；
- mask 与材质相关信息；
- 旋转和变体选择。

修正范围仅限于能够明确确认错误的颜色字段。

### 限定处理对象

判定至少需要三个维度：

1. Pawn 的种族或兼容种族关系；
2. 当前 BodyAddon 的语义部件；
3. 触发目标外观行为的基因或扩展状态。

只按纹理名称判断容易误伤使用相同资源命名约定的其他种族。

### 缓存与分配

渲染路径属于高频执行路径。实现应：

- 缓存反射结果和能力探测结果；
- 颜色一致时直接返回原 Graphic；
- 避免在每次调用中枚举全部基因或全局 Def；
- 将诊断日志限制为一次性或显式调试模式；
- 在状态改变时刷新缓存，而不是永久绕开缓存。

## 失败策略

运行时补丁是兼容增强，不应成为启动硬门槛：

- 找不到可选类型：停用该适配能力；
- 找不到预期签名：记录一次诊断并退回原结果；
- 颜色计算失败：保留原 Graphic；
- 个别 Pawn 数据异常：隔离该对象，不能中断整个绘制流程。
