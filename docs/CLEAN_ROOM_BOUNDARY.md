# Clean-room 与材料边界

## 目标

本仓库用于解释兼容 Mod 的技术结构，不承担完整源码发布、发行包镜像或第三方材料归档功能。应能从仓库历史中证明：公开或共享的每一笔提交都没有纳入被排除材料。

## 可保留内容

- 本仓库原创的架构说明、流程图和约束分析；
- 使用虚构类型、虚构 DefName 和明显占位值的概念示例；
- 对第三方项目名称、作者、工坊链接和事实性功能背景的引用；
- 不包含生产数据或完整实现的测试与验证原则。

## 必须排除的内容

- 来自参考 Mod 的图片、纹理、mask、宣传素材及其他第三方美术材料；
- 从第三方 XML 继承的完整名称集合、概率表和偏移坐标；
- 完整生产 XPath、纹理路径白名单及 Harmony 注册代码；
- DLL、PDB、MDB 或其他可反编译、含本地路径的构建产物；
- `About/PublishedFileId.txt` 等 Steam 创意工坊发行包元数据文件；
- 能直接复制到 RimWorld `Mods` 目录运行的目录结构。

## 示例编写规则

概念示例必须同时满足：

1. 使用 `Example*`、`Placeholder*` 等虚构标识；
2. 数值使用明显占位值，并附不可用于发行的说明；
3. 省略程序集、命名空间、真实方法签名或适配细节；
4. 不能通过替换几个名称就还原完整生产实现；
5. 不引用第三方纹理路径或完整数据表。

## 发布前门禁

每次提交或推送前至少检查：

- 仓库内无 `.png`、`.dds`、`.dll`、`.pdb`、`.mdb`；
- 无 `Textures/`、`Assemblies/`、`About/Preview*`；
- 无真实发行包目录和 `About/PublishedFileId.txt` 等发行包元数据文件；
- 无来源参考目录的逐字节重复文件；
- 无完整概率表、位置坐标矩阵和纹理路径清单；
- `git log --all --stat` 历史也满足上述条件，而不只是当前 HEAD；
- GitHub 仓库可见性与当前发布决定一致。

## 历史门禁维护

`scripts/check-boundary.py` 以及其他受历史 blob 审批保护的敏感示例发生修改后，旧版本仍然存在于可达 Git 历史中，因此不会因为 HEAD 已更新而自动视为安全。

- 更新这些文件后，应先人工确认旧 blob 仍符合本仓库的 clean-room 边界；
- 确认无误后，再将旧 blob SHA 加入 `APPROVED_HISTORICAL_BLOBS`；
- 不得仅为消除 CI 失败而登记未经审查的 blob；加入审批表本身即表示该历史版本已完成审查；
- 历史门禁要求完整 Git 历史；浅克隆需要先获取完整历史后再运行检查；
- CI 必须使用完整历史 checkout，并对所有 push refs（分支与 tag）及 pull request 运行门禁，避免新增可达历史在未检查的情况下留在远端。

## 与完整开发仓库的关系

完整 Mod 应保存在独立的私密开发仓库或离线归档中。架构仓库不设置指向完整仓库的 Git 子模块，不从其构建发行包，也不通过 Git LFS、Release 附件或 Actions Artifact 绕过材料边界。
